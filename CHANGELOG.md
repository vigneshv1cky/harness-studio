# Changelog

Changes to the downloadable Harness Studio app. The plugins in [`plugins`](plugins) keep their own versions.

## 0.3.1 — 2026-10-20

### Added
- **Sponsor the project:** the repository has a Sponsor button and the README a Support section linking to [GitHub Sponsors](https://github.com/sponsors/vigneshv1cky), [Ko-fi](https://ko-fi.com/vigneshmurugan) and [PayPal](https://paypal.me/VigneshV1cky).
- **Search in Settings:** a search field at the top of the Settings page list (⌘F or Ctrl+F while Settings is open) finds any row on any page, such as "network" or "speech", and lists each match with its page. Choosing one opens that page, scrolls to the row and highlights it; Escape clears the search. The index starts with every page's rows and adds whatever a page shows each time you open it, so new rows and plugin cards become findable too.
- **About page brought up to date, with who makes the app:** a new Making things section covers documents, design boards, desktop and mobile apps, live dashboards, charts and diagrams, and speech to text; the right panel, Files (video and audio with the marking bar), smaller requests (old images and earlier reasoning) and helper agents describe what they do now, and Not yet lists the planned design canvas, image generation, templates and the separate video app. A Made by card gives Vignesh Murugan's email, GitHub, LinkedIn, Instagram and X and the machine the app is built on (a 13-inch MacBook Air with the Apple M1 chip, 8 GB of memory and 512 GB of storage), which also appear in the README's new Author section and in each plugin's package details.

- **Live dashboards:** ask for a dashboard and the agent builds a page of charts and numbers with a small refresh script per data source: a spreadsheet or CSV file, a database or warehouse through your own login (BigQuery, Snowflake, Databricks, PostgreSQL, MySQL and others), or a web API with a key kept in a git-ignored file. It shows in a new Dashboards pane, which fetches fresh data by itself every time you open the dashboard, without asking the agent. The first time, the pane shows every refresh file's full text and asks you to approve; approval covers that exact text, so any change to the scripts, the agent's included, asks again, and the agent cannot approve for you. The scripts run with the same sandbox and network setting as the agent's commands (never with full access), up to a minute and 2 MB of output each; the page itself has no network and only receives the data, never commands, keys or logins. **Refresh** runs them again, and the page can ask for a refresh too.
- **Dashboards stay current while closed:** **Keep fresh** in the Dashboards pane (or the agent, through a new kind of watch) refreshes a dashboard every 15 minutes for up to 7 days, through Watches, without waking the agent; it runs only the approved scripts and stops refreshing if they change.
- **Save a dashboard snapshot to send:** **Save snapshot** writes one HTML file with the data as it is at that moment and no refresh, which opens in any browser; nothing is uploaded anywhere. There is no hosted or network link, on purpose.
- **Database logins for commands:** Settings → Permissions → Cloud logins for commands now also offers Snowflake, Databricks, PostgreSQL and MySQL, so `snow`, `snowsql`, `databricks`, `psql`, `pg_dump` or `mysql` can run as you. Each is off by default, and the first command using one in a session asks you once.
- **Dictation:** Harness's Voice Input is now on in Harness Studio: the microphone button between the model picker and Send records you and puts what you said into your message, recognized on this computer by Harness's local SenseVoice model (Chinese, English, Cantonese, Japanese, Korean or automatic). The first use asks to download the model (about 241 MB from Hugging Face) and macOS asks for the microphone. While recording, a language menu beside Stop switches the language for that recording and saves it as the Voice Input setting, so the next one starts with it. It is switched on once, in new and existing profiles; switched off on the Plugins page, it stays off.
- **The agent can transcribe recordings and videos:** a new transcribe tool turns the speech in an audio or video file, or in a part you marked in the Files tab ("[clip.mp4, 1:10.4 to 1:25.0]"), into text in pieces of about 30 seconds, each with its time range, so the agent can say where something was said. It uses the same local recognizer, one piece at a time, so no audio leaves the computer and memory stays low.
- **ffmpeg on first use:** when the agent needs ffmpeg and you have none, it asks once and downloads FFmpeg 9.0.2 (ffmpeg and ffprobe, a 57–68 MB download and about 130–160 MB unpacked, GPL builds from ffmpeg.martin-riedl.de) for macOS or Linux, checks both files against their pinned SHA-256, and installs them sandboxed into Harness Studio's data folder, where every command the agent runs finds them. Settings → Data lists them so you can delete them; an ffmpeg you installed yourself is used instead.
- **Mark parts of a video or audio file for the agent:** under a video or audio player in the Files tab, a bar attached to the player shows the time and a track with the marked part; Set start and Set end (or I and O) mark a part, and Add to message, greyed out until both are set, puts it into your message as a reference (for example "[clip.mp4, 1:10.4 to 1:25.0]"), so "cut this" or "add a caption here" reaches exactly that part. The agent does the edit with ffmpeg; there is no hand-editing timeline.
- **Videos and audio play in the app:** MP4, M4V, MOV and WebM videos, and MP3, M4A, AAC, WAV, OGG, Opus and FLAC audio, open in the side preview and the Files tab with the player's own controls, so a recording or a voice-over can be checked beside the chat. A file whose codec the app cannot decode says so instead of showing a blank player.
- **Desktop and mobile apps:** a native-apps skill tells the agent how to build, run and check Mac, iPhone, Android and Linux desktop apps inside the command sandbox: where each toolchain must keep its files (Swift's own sandbox cannot run inside ours, Gradle and Android write to the home folder), how to check a running app through computer use or a headless Android emulator, and what this computer cannot do (iPhone apps need Xcode; Mac and iPhone apps cannot be built on Linux). Live tests built and clicked through a Mac app and an Android app.
- **Design boards:** asking the agent to design or mock up screens now produces a design board: one HTML file showing each screen and variant side by side at 375, 768 and 1440 pixels wide, in the project's own colours and fonts, with pan and zoom. It opens in the preview pane or any browser and needs no server or network.
- **Design pane:** design boards the agent writes now open in a Design pane beside the chat (its icon sits after Files in the conversation header) and reload whenever the agent changes them, keeping your zoom. A list in the pane's header holds every board in the session's `designs` folder, newest first. Clicking a screen's name, or an artboard with **Pick** on, puts a reference such as "designs/habit-settings.board.html, Home: compact list at 375 px" in your message, so "make this denser" reaches the right screen. Boards run their own scripts in an isolated frame with no access to the app and no network requests of their own (web fonts and images still load); boards made before this get the new board viewer when shown, and their files are left unchanged.
- **Boards pan and zoom wherever the pointer is:** scrolling or dragging over a screen moves the board instead of scrolling inside that screen, Ctrl or ⌘ with scroll zooms anywhere, and every screen shows at its full length, also in the Design pane. The board's **Use screens** button (Escape to stop) lets you click and scroll inside the screens.
- **Charts, icons and diagrams:** the agent makes editable native charts inside PowerPoint and Excel files, and SVG files for standalone charts, icon sets and diagrams, checked against the data, with nothing to install.
- **The agent checks web pages at phone, tablet and desktop widths:** two new Browser pane tools let the agent set the page's width (the page itself reports exactly that width, e.g. 375, 768 or 1440, whatever the pane's size) and take a screenshot it can see, scrolling down long pages. After building or changing a web page it is told to check it at about 375, 768 and 1440 pixels wide and fix what breaks. You watch it happen in the pane; screenshots need the window on screen, and the agent is told to ask when it is hidden.
- **Cloud logins for commands:** Settings → Permissions → Cloud logins for commands lets the agent's commands use your existing Google Cloud, AWS, Azure or Kubernetes login, so `gcloud`, `aws`, `az` or `kubectl` run as you without signing in again. Each is off by default; the first command using a login in a session asks you once, and the rest of that session's commands for it run without asking. Azure and Kubernetes logins are now hidden from commands like the others until you switch them on.
- **A Claude Code-style terminal chat:** `harness-studio` with no task now draws a full-screen chat in the terminal, accented in the logo's blue: a welcome box, your messages and the answers in the terminal's own scrollback, tool calls as `⏺ bash(List files)` with `⎿  Done` under them, a spinner with the elapsed time while the agent works, a bordered input box (Enter sends, `\` then Enter for a new line, ↑ ↓ for earlier messages, Esc stops a reply, Ctrl-C twice quits) and the status line under it. Typing `/` opens a menu of commands (↑ ↓, Tab completes, Enter runs), and an approval appears as a box with **Yes, once** and **No** (No selected; arrows and Enter, or 1 and 2; Esc says no). `--plain`, a terminal narrower than 40 columns or `TERM=dumb` keeps the plain line chat.
- **Approvals and commands in the terminal chat:** an action that needs your approval asks `Allow once? [y/N]` on the input line, answered only by what you type after the question appears (Enter, `n` or Ctrl-D say no). `/help` lists the commands: `/compact`, `/plan`, `/permission` and `/goal` work as in the app, `/clear` starts a new session and `/model` shows the model; a mistyped command is never sent to the model. Each reply ends with a status line: model, tokens, context use and permission mode.
- **Edit any section of the system prompt:** the Instructions page lists the system prompt's sections. **Open** makes your own copy of one section and opens it in your text editor; once you change it, that copy is sent in place of Harness's text for that section only (opening without changing anything does nothing); **Reset** goes back to Harness's text. Other sections keep updating with Harness.
- **Long turns:** a request that takes 60 steps now asks before continuing (Settings → Permissions → Long turns: 60, 120, 200 or never). Halfway there the agent is told to sum up and ask you if it is stuck, and the agent is told when a tool keeps returning exactly the same result, so a stuck agent no longer runs on, spending tokens, until you press stop.
- **AGENTS.md for this repository:** tells coding agents, Harness Studio's own included, that changes to a plugin's host half or to Harness need an app restart they cannot do themselves, so they say so instead of investigating.
- **Your additions to the system prompt:** the Instructions page shows Harness Studio's system prompt read only, and under it a **Your additions** text you can add, edit and remove. It is appended at the end of the prompt for every session, so plan mode and tool guidance keep working and it keeps applying after updates.
- **Unsend:** a message you send while the agent works shows **Unsend** beside it until the agent reads it at its next step; clicking it takes the message back and puts its text into the message box. Messages with images or files cannot be unsent.
- **Queued messages in the chat, like Claude Code desktop's:** messages you queue while the agent works (Cmd/Ctrl+Enter) appear at the end of the conversation as faded bubbles labelled "Queued", with edit, remove and send now on hover, and each goes out as its own prompt, in order, when the agent is free.

### Changed
- **Header menus match Harness's own:** the Panes, Dev servers and More menus use Harness's menu design: compact rows, a slightly see-through card over the menu blur, 14px icons, a check beside each open pane, hairline separators, and arrow keys, Home, End and Escape to move through them.

- **Old screenshots and frames leave the conversation:** an image the agent viewed through a tool (a screenshot, a rendered video frame, a design check) is now sent to the model only for the five steps after it arrived; after that the model sees a short note naming the file and where to view it again, and keeps everything it wrote about the image. Images you attach to your own messages stay. Long visual sessions therefore stop growing by about 1,000 tokens per image on every step: in a 24-frame test the last step sent about 36,000 input tokens instead of about 55,000. Each dropped image makes the model provider re-read the last few steps once without its cache, so a short visual task can cost slightly more while a long one costs about the same or less. The chat and the session log still show the original images.
- **The Flash model no longer re-reads its old reasoning:** each request to DeepSeek-V4.1-Flash used to carry the model's reasoning from every earlier turn of the chat, nearly half of a long chat's input. Now only the current turn's reasoning is sent: everything since your latest message, kept across the agent's tool calls. On a 170-step, five-turn video chat this would cut the last request from about 442,000 to about 251,000 tokens and the whole chat from 42.0M to 27.2M tokens sent. Each new message makes the provider re-read the previous turn once without its cache, about 160,000 extra uncached tokens over that chat's four new turns, which is still about 31% cheaper overall if uncached input costs ten times cached input. A live two-turn test was accepted and answered correctly. DeepSeek-V4-Pro is unchanged, and the chat and the session log still show all reasoning.
- **The agent hands big look-and-read jobs to helper agents:** a new system-prompt entry tells the agent when Harness's helper agents are worth it, as Claude Code does: a self-contained piece whose files, search results, images or logs are not needed afterwards, only its conclusion, and independent pieces in parallel, but not one quick lookup. Until now it had no such guidance, and a product-video chat read about 70 frame images itself, so each step re-sent about 370,000 tokens. In a live test, the same kind of chat handed its image check to one helper (which read 22 images), read 6 images itself instead of 27, and each step grew by about 1,500 tokens instead of 2,500 (with old images also dropped from context).
- **A tidier header:** the top right keeps Terminal, Browser and Files as icons and puts every pane in a Panes menu beside them, with a tick on the open ones; Watches moved into that menu, and its eye appears in the header only while watches are running.
- **Up recalls only this chat's prompts:** the arrow keys in the message box now step through the prompts sent in the chat you are in, read from the conversation itself, instead of one list shared by every chat; the old shared list is deleted.
- **Waiting questions and approvals stand out in the conversation:** a question or plan-review card has a clear grey border and a soft shadow on the message box's surface, and an approval card keeps its amber border with the same shadow, so neither disappears into the chat.
- **Questions and approvals appear in the conversation, like Claude Code desktop's:** when the agent asks a question or needs an approval, its card appears after the last message and the chat scrolls to it, while the message box stays below it instead of being replaced. Typing in the message box and sending answers the question shown on the card, as its own answer, then moves to the next question or submits on the last one. While an approval waits, a message you send stays in the box with a notice until you allow or reject the request. The empty message box says what is waiting ("Answer the question above…" or "Allow or reject the request above first"). A plan review's **Request changes** keeps the card and puts the cursor in the message box; what you send there goes back to the agent as your change request. A question card no longer takes the keyboard when it appears.
- **Full screen shows one pane:** a pane in full screen fills the window alone. The other pane is hidden, not closed, comes forward from its header icon, and both show stacked again when full screen ends; a pane that opens during full screen, such as the Design pane opening on a new board, takes the screen.
- **Pick and Annotate moved into the Browser pane's header**, beside Dev servers and ⋮, so they no longer float over the bottom of the page.
- **Settings has more pages:** General keeps how the chat behaves (work details, links, sending while busy, shortcuts, version). Appearance holds language, light or dark, colour theme and fonts; Permissions holds the permission mode, network for commands, cloud logins, long turns and always-allowed sites; Computer use and Data are pages of their own. The new pages have their own icons, Harness Studio's rows keep the same look on every page, and row names are in sentence case ("Light or dark", "When to collapse work details").
- **The terminal chat shows its work as it happens:** the answer appears as the model writes it instead of when the turn ends, each tool call and its result take one line (`• bash List files`, then `✓` or `✗` with the error's first line), and a retried request is marked. Text from the model is shown with control characters escaped, so a page the agent read cannot make it clear your screen, retitle the window or write your clipboard.
- **The Instructions page opens files in your text editor:** every instruction file and Your additions to the system prompt now have **Open**, which opens them in your text editor (creating a missing file empty first), instead of an editor inside the page; Remembered notes get **Open** too. The page refreshes its sizes when you switch back to Harness Studio.
- **Fewer steps per request:** the default instructions now tell the agent to run independent reads and commands together, read a region once, and not re-read a file after a successful edit. Each step resends the whole conversation, so this saves time and tokens. A global AGENTS.md you already have is not changed.
- **Messages you send while the agent works reach it at its next step**, as in Claude Code, instead of waiting until the whole turn ends. Cmd/Ctrl+Enter still queues a message for after the turn, and Settings → General → Send behavior while busy switches the two; a choice made there is kept.
- **Model and access menus back inside the message box**, on its bottom row with + and send; the usage readings sit centred under the box, and the text lines up with the + button.
- **No previews on hover over files in the chat:** changed-files cards and image links no longer pop up a preview; clicking still opens the file.
- **A cleaner About index:** "On this page" with each section's number, only the section being read expanded with the current feature marked, shown beside the text in a normal window and as a "Jump to" menu in a narrow one.

### Fixed

- **The window no longer goes blank for good when the app swaps its own parts while running:** when the app replaced several of its built-in parts in place (every time Harness was rebuilt while the development app was open), the parts that own the session list and the main view were missing for a moment. The window treated that as a fatal startup error and stayed empty until the app was restarted, although nothing else had stopped. It now waits for the replacements: in a live test the window flickered for under a second at a time over about five seconds and came back with the sidebar and a chat. The chat it returns to can be a different one from the chat that was open.
- **Database login files are hidden from the agent's commands:** Snowflake's connections file, `~/.databrickscfg` and `~/.databricks`, `~/.pgpass` and `~/.pg_service.conf`, and `~/.my.cnf` and `~/.mylogin.cnf` were readable by the agent's commands, so a prompt injection could have had a command read and send them. They are now hidden like SSH keys and cloud credentials, until you switch the matching login on.
- **The harness-studio command ignored the model key saved in the app** and worked only with `DEEPSEEK_API_KEY` exported in the shell. It now uses the saved key; the environment variable still works when nothing is saved.
- **A message sent while the agent works restarted the Long turns count**, so a long turn could keep going without the halfway reminder or the pause. The count now runs from the start of the turn.
- **The "/" and "+" menus were see-through in dark mode**, so the conversation showed through their items; menus are solid in both themes.
- **"N queued messages" overlapped the usage line** under the message box, and the context percentage ran into the model name once the model showed a badge.
- **The tooltip on a reply's branch button was cut off** at the left edge of the conversation.

- **Built on Harness 0.2.1-rc.2** (was 0.2.1-alpha.3), through Harness Studio's own fork of Harness, [harness-studio-core](https://github.com/vigneshv1cky/harness-studio-core), instead of patch files. Upstream's changes since alpha.3 come with it, among them a DeepSeek Search and Fetch option for web tools and a model badge for the latest DeepSeek Flash.

## 0.3.0 — 2026-10-18

Includes the 0.2.1 changes below, which were not published as a separate release.

### Added

- **Computer use in the downloadable app (macOS):** the agent can see and control apps on your Mac, one approved app at a time, as it already could in a development build. The app now ships the native helper and turns computer use on by itself; Settings → General → Computer use shows the two macOS permissions it needs. While the app is not signed with a Developer ID, macOS may ask for those permissions again after each update.
- **Chat in the terminal:** `harness-studio` with no task opens a chat: each line you type is one message in the same session. Ctrl-C stops a reply, Ctrl-D or `/exit` quits, and the session id it prints continues the chat later with `--session-id`. Piped input and `--json` work as before.
- **The terminal command on Linux:** the .deb now installs `harness-studio` as the command-line tool, as on macOS: give it a task, pipe text into it or use `--json` and `--session-id`. Typing `harness-studio` in a terminal used to open the app; open it from your applications menu instead. The AppImage has no terminal command.
- **The system prompt on the Instructions page:** a read-only System prompt row above the instruction files shows Harness Studio's own prompt as a new session starts with it, with its size, sections and tool count, and Show for the full text, so everything the agent is told before your first message is in one place.
- **Replies like Claude Code's, out of the box:** the first start writes a default reply style as your global instructions, shown in the Instructions tab as "Global, all projects": the agent leads with the answer, keeps replies as long as the request needs, uses lists and tables only when the content calls for them, links files, gives a one-line note before each batch of tool calls, and ends with what changed and how it was checked, including what failed or was not verified. Edit it there like any instruction file. It is written only when you have no global instruction file yet, and never again after you change or delete it.
- **Every file in the Files tab, like Claude Code:** the Files tab now shows PDFs, images, spreadsheets, and Word and PowerPoint documents with Harness's own viewers, and file cards, file links and references in the chat open their file there (with the tree hidden) instead of in a separate preview. Markdown, web pages, CSV files and SVG images have a Rendered / Source switch, Source being the editor; both start in the view you chose last. CSV files render as a table in the app's table style, Excel workbooks in a cleaner spreadsheet (sans-serif cells, the app's type on the formula bar and sheet tabs), every spreadsheet cell centred, and in full screen the tree shows by default.
- **Chrome picks are authenticated:** elements picked in Chrome reach Harness only over polls signed with a key the Chrome bridge makes at each start and hands to Harness over its private pipe, and every answer is signed back. Another program on the bridge's port can no longer collect picks or slip a fake one into a conversation.
- **Your own session in a new worktree:** the New Session screen has a New worktree switch (for git workspaces with commits). With it on, sending the first message first makes a new git worktree and branch from the workspace, and the session works there, so its changes stay apart from yours.
- **Always allow a website:** the new-site approval has a third button, Always allow for this website. The site is saved on this computer and never asks again; Settings → General → Always-allowed sites lists them, each with Remove. Only the exact site is allowed, not its subdomains.
- **Calmer approval card:** the approval prompt is a neutral card like Claude Code desktop's (hairline border, small muted "Waiting for approval" label, 14px question, smaller buttons) instead of an orange-framed warning, and the new-site question is shorter.
- **Your message's time and copy button** sit beside the message instead of under it, so they no longer cover the line that follows.
- **Previous prompts with the arrow keys:** in the message box, Up brings back the prompts you sent, newest first, when the box is empty or the cursor is at its start; Down steps forward and finally returns what you were typing. The last 200 are kept on this computer.
- **Question cards like Claude Code's:** the choices sit straight on the card as soft rounded rows (no inner box or lines), each label over a lighter description, its number in a chip at the right that fills with the accent colour when chosen, and the typed answer as the last row. The send button in the message box is smaller (24px).
- **Clearer full pages:** Plugins, Connectors, Automation tasks, Instructions, About and the Git page draw their separator lines and boxes stronger, and group their lists in rounded, bordered sections with a line between rows (the Git commit list without row lines, so the branch graph stays whole).
- **Colour themes:** Settings → General → Colour theme adds Warm (Claude-like), Graphite, Nord, Solarized and High contrast, each in light and dark, on top of the default look; Appearance still chooses light, dark or system. The app starts in the chosen theme from its first frame, and dark mode no longer starts on a white loading screen.
- **Code like Claude Code's:** code blocks in replies, Markdown files and previews have Claude Code desktop's look: a hairline border on a soft fill, rounded corners, no header bar, with copy and wrap buttons that appear when the pointer is over the block. Inline code uses Claude's smaller chip.
- **One table style:** tables in the conversation, in Markdown files and in a connector's tool list share one look: a rounded border, a shaded header row and light row lines.
- **Git page:** your workspaces' git history, below Instructions in the sidebar, opening over the whole window: an overview of every workspace's branch, upstream and uncommitted files, then one workspace's commits with a branch graph, search by message, author or changed code, each commit's files and diffs, and blame. A Branch menu switches the workspace to another local branch, refused while anything is uncommitted or an agent is working there.
- **Background tasks in the Session pane, like Claude Code desktop's:** one card lists what is still working for the session: commands the agent left running in the background, workflows, subagents, programs in the agent's terminal and watches, each with its running time and a stop button. Finished ones are behind an "N finished" row, newest first. One compact line per task.
- **Command rules, like Claude Code's:** rules that block a tool call or ask you first, in Claude Code's `permissions` format, in `~/.harness-studio/permissions.json` and a project's `.harness-studio/permissions.json`. Bash rules check each part of a compound command and also cover the agent's terminal and Watch commands; Read and Edit rules take paths; WebFetch rules take a domain; connector rules name a server or tool. Deny wins over ask.
- **Your data:** Settings → General → Your data lists where Harness Studio keeps things on this computer, with each part's size and an Open button.
- **Asking before new sites:** web fetch, Browser pane pages the agent opens and pages it opens in your Chrome now ask before reaching a site for the first time in a session; once allowed, the session reaches it again without asking. A prompt injection could otherwise have the agent put what it has read into a web address, and none of these goes through Network for commands. Sites on this computer pass, as do the sites on the Network for commands list while it is set to Only allowed sites. Full access lifts the check. The command-line tool does not ask.
- **Ask before calls, per connector:** each connector can now ask before every call, or only before calls to tools its server does not mark read-only. Off by default.
- **Secret files are hidden from the agent:** commands the agent runs and its file tools can no longer read SSH keys (`~/.ssh`, except `known_hosts` and `config`), cloud and registry credentials (`~/.aws`, `~/.config/gcloud`, `~/.docker/config.json`, `~/.npmrc`), password files (`~/.netrc`, `~/.git-credentials`), `~/.env`, Harness Studio's own key store, or `.env` files outside the workspace. A prompt injection in a README or web page could otherwise have the agent read one and send it anywhere. The workspace's own `.env` files stay readable. A command that genuinely needs a key, such as git over ssh without an ssh agent, fails until you approve it with full access. On Linux, `.env` files in other projects are not covered, and hosts without bubblewrap do not hide these files from commands.
- **Full-screen programs for the agent:** a real terminal the agent can drive: it starts a program (vim, less, top, an installer that asks questions), reads the screen as text and sends keys, waiting each time until the screen settles. Programs run under the session's sandbox and network setting, up to four per session, and close when the session ends, after 30 minutes unused, or when the sandbox setting changes. Terminal is the ninth built-in plugin.
- **Code editor:** files you open in the Files tab open ready to edit (CodeMirror), and Edit on a file preview opens one in an editor tab, with syntax colours, search and replace, multiple cursors and folding; ⌘S saves. Changes on disk appear in place while you have no unsaved edits; otherwise a bar asks which version to keep, and a save never overwrites a change you have not seen. Text files inside your workspaces, up to 2 MB. Editor is the tenth built-in plugin.
- **Browser DevTools for the agent (desktop app):** on your own development pages (localhost and your local network), the agent can read the Browser pane page's network requests (status, failures, and filtering), any response body, and its console with uncaught errors and their stack traces. Requests are recorded from the page's first load. DevTools never attaches to public sites, which can detect it, and detaches when a page leaves a local address.
- **Watches:** cheap checks that wake the agent only when something changes — a command's output (git status, a linter), a port on this computer going up or down, or files changing. They run on your computer without the model, commands under the session's sandbox and network setting; only an idle agent is woken, never by its own work, with a cooldown between notices and a notice limit. The eye button in the session header lists them, removes them and adds one. Watch is the eighth built-in plugin.
- **Command-line tool (macOS):** app menu → Install Command-Line Tool adds `harness-studio`. `harness-studio "task"` (or text piped in) runs one session in the current folder and prints the answer, with the app's model key, settings, connectors, memory and hooks; `--json` and `--session-id` are available for scripts and CI.
- **Network for commands:** Settings → General → Network for commands can turn the internet Off for commands the agent runs, or allow Only the sites you list (it starts with npm, PyPI and GitHub). The operating system blocks direct connections; listed sites go through a small built-in proxy, and other sites are refused with a message naming them. The default stays On. On Linux this needs bubblewrap.
- **Undo file changes, like Claude Code's rewind:** before the agent first changes a file in a turn, a copy is kept. Under each turn that changed files, Undo file changes puts them back as they were before that turn (and undoes later turns too), removes files the agent created, and tells the agent. Changes made by shell commands are not covered. Undo is the seventh built-in plugin.
- **About page:** an About row under Settings at the foot of the sidebar opens a page that explains everything Harness Studio does: the agent loop and its tools, plan mode and access modes, instructions, memory and compaction, connectors, helper agents, hooks and sessions, the sandbox, and what is not there yet. Each feature says what it does, how it works and why.
- **Hooks, like Claude Code's:** your own commands that run before a tool call (and can block it or ask you first), after a successful one (and can send the agent feedback), and when the agent is about to finish (and can send it back to work, for example until the tests pass). The file format is Claude Code's, so hooks can be copied over. Yours live in `~/.harness-studio/hooks.json`; a project's `.harness-studio/hooks.json` runs only after you allow it on a card. Hooks is the sixth built-in plugin.
- **Auto memory, like Claude Code's:** the agent keeps notes for itself as it works in a project, without asking: one small file per fact (what it is, why, and how to apply it) plus a `MEMORY.md` index, in `~/.harness-studio/memory/<project>/`. New sessions in the project read the index, so a correction or preference carries over without being repeated. The Instructions page lists each memory with Open and Delete. Secret-looking text is refused.

### Changed

- **About page:** a new Panes and pages section covers the right panel and its layout menu, the Session pane with Background tasks, the Changes pane, Files, the Terminal and the Git page; editing files and the agent's choice between the Browser pane and your Chrome are described as they now work.
- **Plan mode is enforced:** while it is on, the session is read-only, so the agent cannot change files, even with an approved escalation, until you approve the plan or switch plan mode off. Before, plan mode only asked the agent not to edit.
- **Remember** now offers a card only when you ask the agent to add a rule to your instruction files; everyday corrections and preferences go to auto memory instead.
- **Instruction files are Harness Studio's own:** sessions read your personal `~/.harness-studio/AGENTS.md`, then each project folder's `AGENTS.md` from the repository root down, each followed by its `AGENTS.local.md` — Claude Code's three levels, with Harness Studio's file names. Files written for other agent tools are no longer read: not `CLAUDE.md`, `CLAUDE.local.md` or `~/.agents/AGENTS.md`. The Instructions page lists only these files. To keep a project's `CLAUDE.md` rules, move them into `AGENTS.md`, or make `CLAUDE.md` a link to `AGENTS.md` so both tools read one file.
- **Instructions page:** the personal row is named "Global, all projects". Long paths keep their folder and file name visible and shorten the middle, with the full path on hover.
- **Left sidebar is more compact:** 26px rows (13px text, as before) and a shorter Workspaces header, so more sessions fit now that the sidebar also has Instructions and About.
- **Right panel:** Files, Terminal, Browser and the other right tabs first open at 35% of the window instead of 45%, so the conversation keeps most of the width. Dragging it wider still works.
- **Pane layout button:** each pane header has a layout button next to expand. Clicking it opens the menu for moving the pane, filling the panel and opening it in a new window; clicking again, pressing Escape or clicking elsewhere closes it. The expand button only expands, and nothing opens on hover.

### Fixed

- **The downloadable build stopped at its type check:** twelve type errors in tests added or changed by the Browser DevTools, secret-file, stress-fix and computer-use patches (and one in the plan-mode test) failed the full build that packaging runs, and three menu tests still expected "Manage dsh Command…" after the menu item became "Install Command-Line Tool…". The tests are corrected inside the patches that introduced them; the app's behaviour is unchanged.
- **Browser tabs:** + in a browser pane opens the new tab in that pane; with two stacked browser panes it opened in the other one.
- **The app could fail to start after many launches** ("Web request failed", then restarting again and again): each launch left one more sign-in cookie for 127.0.0.1 until requests carried so many that the app's own server refused them. Old sign-in cookies are now removed at startup.
- **The terminal command did not start:** in 0.2.0 and 0.2.1 the command installed from the app menu looked for an executable named after DeepSeek Harness and failed. It now starts Harness Studio, and uses Harness Studio's home folder instead of Harness's.
- **Dates on remembered notes and memories** are the local date; they were the UTC date, a day ahead in the evening in the Americas and a day behind in the morning further east.
- **Sidebar scrollbar in the light theme:** the workspace list's scrollbar was drawn almost the colour of the sidebar and was hard to see. It is now a visible grey in both themes, and still hides when the pointer leaves the sidebar.
